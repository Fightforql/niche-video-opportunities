5 分钟速读
  • 一句话：给一张用户现场图 $I_0$ 和逐步文字 $\{\tau_i\}$，一次生成与现场相符的离散步骤图像序列，每一步一张图。
  • 真正贡献：从 HowTo100M 自动挖出 57.8 万条序列、450 万个步骤、25,026 个任务；再把 DynamiCrafter 改成逐帧接收不同文字条件、支持可变长度的序列生成器。
  • 关键机制：输入图像 latent 被复制到每个目标位置以锚定场景；第 $i$ 张图只对自己的步骤文字 $\tau_i$ 做 cross-attention；时序注意力让所有步骤共享上下文。
  • 重要边界：论文输出不是“手如何连续移动”的操作视频，也没有验证扭矩、接触关系或安全动作。它更像自动生成的分镜式图解说明书。
  • 商业价值：适合低风险、高 SKU、说明经常改版的售后视觉卡片；高风险维修只能把它当草稿生成器。

读数提醒

论文的 0.52 Step Faithfulness、0.34 Scene Consistency、0.42 Task Faithfulness 是特定 CLIP/DINO 检索或分类协议下的平均分，不是“52% 步骤正确率”“34% 现场还原率”或“42% 任务成功率”。

TL;DR

ShowHowTo 把视觉教程重新表述为“用户现场条件下的状态快照序列”。相较逐张独立生成，它把全部步骤放进一个带 temporal attention 的 latent video diffusion U-Net，使模型能在同一轮去噪中兼顾步骤变化和场景保持；相较普通视频模型，它让每个输出位置接收不同的步骤文字。

论文最扎实的部分是数据管线：WhisperX 转录，Llama‑3.1 判断视频是否具有教学性并抽取带时间区间的步骤，DFN‑CLIP 在区间内选代表帧，动态规划约束帧的时间顺序。它解决了“无大规模逐步图文数据”的瓶颈，但也把语音、LLM 和 CLIP 的误差一层层带进数据。

最终结果表明专用方法在“既像输入场景、又像对应步骤”的折中上优于五个相关生成方法。它仍不理解真实物理过程，且自动评估与数据筛选都使用 DFN‑CLIP，存在闭环偏差。因此商业系统应把生成结果置于结构化 SOP、部件图和专家签核之后。

1. 问题、动机与研究脉络

生活化直觉

文字说明“把密封圈装进凹槽”并不够。用户想看到自己的泵体、自己的零件和正确装好后的状态。逐张画图会让泵体换型号；普通视频模型又倾向生成一个短动作，而不是五个语义跨度很大的里程碑。

设任务 $T$ 有 $n$ 个步骤。输入是现场首图 $I_0$ 和文本序列 $\tau_0,\tau_1,\ldots,\tau_n$，输出是 $\hat I_1,\ldots,\hat I_n$。目标同时包含三件互相拉扯的事：每张图对应自己的步骤；器具、台面、视角尽量继承 $I_0$；整个序列表达完整任务。

timeline title 从单步编辑到场景化步骤序列 2022 : InstructPix2Pix：文本驱动单图编辑 2023 : DynamiCrafter：输入图像动画化的视频扩散先验 2024 : GenHowTo：从教学视频学习单次动作/状态变换 2024 : StackedDiffusion：把 WikiHow 多步图拼成一张图生成 2025 : ShowHowTo：现场图 + 每步文字，生成可变长步骤图序列

发展逻辑：单图编辑能保现场但容易累积误差；无条件序列生成能讲步骤却丢现场；ShowHowTo 把二者合在同一时序生成过程中。

本文研究的是离散“关键状态”，不是动作轨迹。对售后说明很合适，对示范手法、力度与时序则证据不足。

2. 数据挖掘：从百万教学视频到步骤图文序列

作者处理约一百万条 HowTo100M 视频，最终得到 578K 个序列、4.5M 个 image-text steps、25,026 个任务。整个流程不依赖人工逐帧标注。

flowchart LR A[HowTo100M 视频] --> B[WhisperX 转录\n句级时间戳] B --> C[Llama-3.1-8B-Instruct\n教学视频过滤] C --> D[Llama 3\n抽取步骤 + 起止时间] D --> E[时间窗向两侧扩展 ε=15s] E --> F[DFN-CLIP 打分候选帧] F --> G[动态规划\n选择单调递增关键帧] G --> H[步骤文字—代表图序列]

2.1 转录与视频过滤

原 HowTo100M 的 YouTube ASR 有断句和词错问题，作者改用 WhisperX。随后 Llama‑3.1‑8B‑Instruct 根据标题和转录片段判断视频是否真的在教一件事。人工检查的平衡集含 200 个视频，过滤器 false positive 为 5%，false negative 为 12%；全量中判定 847K（68.4%）为教学视频，过滤 391K（31.6%）产品开箱、音乐和 vlog 等内容。只处理 10 分钟以内视频，因为更长转录会超过 Llama 3 上下文并降低质量。

2.2 步骤抽取与跨模态对齐

LLM 把转录变成有序步骤并给出每步的起止时间。由于讲解和画面通常错位，检索窗口扩展为 $[s_i-\epsilon,e_i+\epsilon]$，其中论文设 $\epsilon=15$ 秒。对每个步骤文本 $\tau_i$ 和候选帧 $I_t$，DFN‑CLIP 给出相似度；动态规划选择总相似度最大的、时间严格递增的帧序列：

为什么不能每步各自取最高分

“切开”“放入锅里”的局部最高分可能都落在同一张成品画面上，甚至后一操作匹配到更早的帧。动态规划把整个教程当作一条有方向的时间线。

$$\{t_i^*\}_{i=0}^{n}=\arg\max_{t_0\lt\cdots\lt t_n}\sum_{i=0}^{n}s\!\left(\tau_i,I_{t_i}\right),\quad t_i\in[s_i-\epsilon,e_i+\epsilon]$$
是什么
依据论文流程写出的等价优化形式，用来解释动态规划目标；论文正文描述该过程，但没有把它编号为独有公式。
逐符号
$s(\tau_i,I_t)$ 是 DFN‑CLIP 文图相似度；$s_i,e_i$ 是 LLM 输出的时间边界；$t_i^*$ 是最终代表帧时间；不等式保证顺序。
为什么
联合最优比逐步贪心更不容易产生倒序和重复帧。
深入：数据质量到底多可靠？

附录中的人工比较显示：自动选帧优于人工帧 18%，人工帧更好 36%，两者打平 46%。这说明自动化规模很强，但“高质量”不能理解为每个训练对都精准。商业私有数据应增加 OCR/部件识别、步骤状态约束和抽样复核。

数据把连续视频压缩成稀疏的状态节点；下一步模型只需生成这些节点，而无需重建节点之间的动作轨迹。

3. 方法总览

核心一句话：把 $n$ 个步骤当成一段由 $n$ 帧组成的“语义视频”，让第 $i$ 帧读取第 $i$ 条文字，同时让所有帧通过 temporal attention 交换信息，并把现场图 latent 注入每个位置。

模型从 WebVid10M 上训练的 DynamiCrafter image-animation checkpoint 初始化，使用带空间/时间注意力的 latent video diffusion U‑Net。训练时对整个 U‑Net 微调。不同 batch 采用不同序列长度；主模型训练 2–8 步的连续子序列，而注意力结构使推理可以扩展到 1–15 步。

flowchart TB I[现场图 I₀] --> V[VAE encoder E] I --> C[CLIP image encoder] T[每步文字 τᵢ] --> X[逐帧 text cross-attention] V --> R[复制并拼接到每个噪声 latent zᵢ] C --> Y[全局 image cross-attention] R --> U[Spatio-temporal U-Net] X --> U Y --> U U --> D[VAE decoder] D --> O[离散步骤图像 Î₁…Îₙ]

两条场景锚点：VAE latent 的通道拼接保留局部结构，CLIP image feature 的 cross-attention 提供全局语义；逐帧文字决定每个位置应发生什么变化。

4.1 场景条件：把同一现场图送到每个步骤

直觉

每张分步图都在同一张工作台上作画。若只在第一步展示工作台，后续步骤会逐渐“忘记”；所以模型在每个输出槽位都拿到 $I_0$ 的 latent。

$$u_i=\operatorname{Concat}\left(x_{t,i},\mathcal E(I_0)\right),\quad i=1,\ldots,n$$
是什么
论文明确描述的输入拼接，用符号展开表示；不是论文编号公式。
逐符号
$x_{t,i}$ 是第 $i$ 个步骤的带噪 latent；$\mathcal E(I_0)$ 是现场图 latent；Concat 沿通道维组合成 U‑Net 输入 $u_i$。
为什么
每一步都有同等强的像素结构锚点，避免自回归“上一张错一点、下一张错更多”。

4.2 逐步骤文字条件

直觉

普通视频的一句 caption 可以覆盖全部帧；教程的“取下旧滤芯”和“装入新滤芯”却不能共用一句模糊摘要。ShowHowTo 让第 $i$ 帧只查询第 $i$ 条指令。

$$A_i=\operatorname{softmax}\!\left(\frac{Q_iK(\tau_i)^\top}{\sqrt d}\right)V(\tau_i)$$
是什么
cross-attention 的标准展开，用于说明论文的逐帧条件机制；作者没有提出新的 attention loss。
逐符号
$Q_i$ 来自第 $i$ 帧视觉 latent；$K,V$ 来自 $\tau_i$ 的文本 token；$d$ 是 key 维度；$A_i$ 是注入该帧的文字条件。
为什么
不同输出位置不再竞争一条长 prompt 中的语义，能直接建立“步骤 $i$—画面 $i$”对应关系。

消融最能说明它的重要性：拼接全部步骤成单 prompt 的 Step Faithfulness 为 0.21，LLM 摘要为 0.20，逐帧 prompt 提升到 0.51；再让 $\tau_0$ 使用真实自由文本而不是固定 “an image”，得到 0.52。

4.3 序列联合去噪与训练目标

直觉

模型不是先画第一张再喂给第二张，而是同时把整组噪声变成整组步骤图；因此背景、容器和工具可以跨步骤互相参照。

$$x_t=\sqrt{\bar\alpha_t}x_0+\sqrt{1-\bar\alpha_t}\,\epsilon,\qquad \mathcal L_{\mathrm{denoise}}=\mathbb E\big[\|\epsilon-\epsilon_\theta(x_t,t,I_0,\{\tau_i\})\|_2^2\big]$$
是什么
DynamiCrafter/latent diffusion 的标准噪声预测目标。论文说明沿用预训练视频扩散模型，并未声称这是 ShowHowTo 独有公式。
逐符号
$\bar\alpha_t$ 是累计噪声日程；$x_0$ 是真实步骤序列 latent；$\epsilon\sim\mathcal N(0,I)$；$\epsilon_\theta$ 同时接收时间、现场图和逐步文字条件。
为什么
反向迭代后得到受现场和步骤约束的 clean latent。

4.4 可变长度与 scene consistency 的取舍

主模型按 batch 采样 2–8 步长度；若原序列更长，取连续子序列。推理可生成 1–15 张。短序列背景变化少，容易学会“保背景”；长序列跨台面、炉灶等场景变化多，模型更愿意服从步骤但降低场景保持。8 步上限是两者折中。随机抽取非连续步骤会使 Scene Consistency 从 0.34 降到 0.32。

scene consistency 不是一个额外 loss，而主要来自输入图双重条件、跨帧 temporal attention、连续子序列训练以及数据本身的同视频场景共现。

5. 端到端走一遍：更换净水器滤芯

  1. 现场输入：$I_0$ 是用户手机拍摄的蓝色净水器，右侧有银色接口；SOP 给出关闭进水阀、旋下旧滤芯、装入新滤芯、打开阀门并检查漏水。
  2. 数据形态：构造 $\tau_0=$“蓝色净水器与右侧银色接口”，$\tau_1\ldots\tau_4$ 为四步文字，生成长度 $n=4$。
  3. 编码：VAE 把 $I_0$ 压成 latent；复制 4 份，分别与 4 个带噪 latent 拼接。CLIP image feature 同时进入 image cross-attention。
  4. 逐帧语义：第 2 个位置查询“旋下旧滤芯”，第 3 个查询“装入新滤芯”。若改为合并 prompt，四张可能都画成“手握滤芯”。
  5. 联合去噪：temporal attention 共享蓝色外壳、台面和接口；每步文字推动对应部件状态改变。
  6. 输出与审校：得到 4 张里程碑图，而不是动作连续视频。业务系统必须检查阀门位置、滤芯型号、旋转方向、密封圈和漏水检查；论文模型不会保证这些工程事实。

6. 实验：设置、指标、主结果与消融

先看什么：先看相关方法中的三指标折中，再看逐帧 prompt 和序列长度消融。Stable Diffusion 与 Copy baseline 各自在单项上更高，但前者不保现场、后者不执行步骤。

6.1 指标定义

  • Step Faithfulness：对 $\hat I_i$，用 DFN5B‑CLIP‑ViT‑H‑14‑378 在该序列全部步骤文字中 zero-shot 分类，预测是否为 $\tau_i$。
  • Scene Consistency：用 DINOv2 ViT‑B/14 reg 的平均 spatial patch feature，从测试图集中检索与 $\hat I_i$ 最相似的真实图；判断检索图是否来自 $I_0$ 的同一源视频。检索库排除输入图以避免复制解。
  • Task Faithfulness：平均整条生成序列的 DFN‑CLIP 图像特征，再在全部 200 个测试任务名中 zero-shot 分类。
  • 指标先在每条序列内平均，再跨序列平均。它们是代理指标，并不测量物理正确性或用户能否完成任务。

证据风险

DFN‑CLIP 同时参与训练帧选择、测试样本筛选和 Step/Task 评分，存在评价闭环；主表未给误差条或显著性检验。0.42 与 0.44 之类小差距不应被解释为可靠业务优势。

7. 局限、FAQ 与商业迁移

  • 离散而非连续：每步只有一个关键状态，没有手的轨迹、速度、力度和过渡。
  • 物理正确性未验证：可能画出视觉合理但装配关系错误的零件；failure case 包括罕见工具失败和状态没有随动作更新。
  • 首图约束有限：CLIP/DINO 语义相似不等于 SKU、刻度、接口、标签完全相同。
  • 数据偏差：食品类数据多；附录中 Food 的 Step 为 0.67，但 Scene 仅 0.24。
能直接做维修教学视频吗？

能做“每一步一张图”的分镜卡，再由前端做切换或轻动效；论文没有生成连续示范动作的证据。真正视频需要增加真实片段检索或受控 image-to-video 模块。

Scene Consistency 0.34 是否太低？

它是从整个测试库检索同源视频的 top‑1 命中，不是相似度百分比；不能按“34% 一致”理解，但仍提示场景保持远未解决。

场景生成层作用必须增加的验收
家电耗材更换生成与现场接近的步骤卡部件/方向/OCR 检查，工程师签核
电商安装辅助个性化“下一步长什么样”BOM 完整性、禁忌动作、退货回流
现场技师微课按故障快速编排图解断电/泄压安全 gate，版本追踪

建议 MVP 先选 3–5 步、低风险、外观差异明显的耗材更换；验收用步骤漏检率、部件识别准确率、专家一次通过率和客服处理时长。

  --ckpt_path weights/dynamicrafter_256_v1.ckpt

作者在单节点 8 GPU 上训练，每卡 batch size 2；README 警告 batch size 大于 1 可能需要每卡超过 40GB VRAM。数据目录含 prompts.json 和 imgseqs*；每条序列横向拼成一张宽度 $N\times W$ 的 JPEG，prompt 数必须与 $N$ 相同。服务器图像需以机构邮箱联系作者获取账号，也可按 keyframes.json 从原 HowTo100M 视频提帧。官方使用 ffmpeg 7.0.1、5 fps。

资源：官方代码 · 项目页 · 论文与附录 · DynamiCrafter。

9. 术语表

visual instruction
用一张或多张图表达操作步骤；本文是一系列离散关键状态。
scene-conditioned
生成结果受用户输入现场图约束。
step faithfulness
生成图能否在该序列步骤文字中被 DFN‑CLIP 分到正确步骤。
scene consistency
生成图能否以 DINOv2 特征从测试库检索回输入图的同源视频。
task faithfulness
整条序列平均特征能否在 200 个任务中被分到正确任务。
state transformation
操作前后对象状态的变化。
