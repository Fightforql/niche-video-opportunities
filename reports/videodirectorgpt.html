5 分钟速读
  • 一句话：先让 GPT‑4 把一句需求写成可检查的 video plan，再让 Layout2Vid 按每帧边界框渲染；跨场景重复实体共享同一个视觉 embedding。
  • 核心突破：把“故事、场景、对象身份、位置和运动”从一个模糊 prompt 拆成结构化中间表示，允许人编辑后再生成。
  • 生成器：在 ModelScopeT2V 的 spatial attention 中加入 GLIGEN 风格 Guided 2D Attention，仅训练约 13% 参数，而且只需图像级框标注。
  • 关键数字：VPEval layout overall 70.6%（ModelScopeT2V 40.8%）；方向控制 46.5%（30.5%）；HiREST FVD 733（1322）。
  • 现实边界：每个 scene 仍是 16 帧左右的短片，再串成多场景结果；这不是分钟级连续长视频，也没有声音、剪辑节奏、复杂交互或 3D 几何保证。

TL;DR

VideoDirectorGPT 的价值不在于发明了更强的基础视频模型，而在于把大模型的规划能力与可控扩散渲染结合：GPT‑4 先产出场景描述、实体、背景、逐帧二维框以及一致性分组；Layout2Vid 再把文本、视觉身份和位置编码成 grounding tokens，在 frozen ModelScopeT2V 上控制物体出现在哪里、怎么移动、跨镜头是否保持同一外观。

这套拆分非常接近商业制作流程：计划是可读、可审计、可编辑的；渲染器只负责执行。实验也显示，单纯把更好的 scene prompt 交给 ModelScopeT2V，只能把 HiREST FVD 从 1322 降到 918；加入 Layout2Vid 后进一步到 733，说明 planner 与 renderer 都贡献了增益。

代价是系统高度依赖 GPT‑4 输出格式、边界框能表达的二维约束以及 ModelScopeT2V 的画质。论文的核心公式只有 grounding token 融合式；没有提出新的 diffusion loss。报告下文会严格区分论文独有设计与继承自 GLIGEN/latent diffusion 的标准组件。

1. 问题与研究脉络

生活化直觉

让剧组拿一句“做草莓甜点”直接拍，演员、道具、站位和场景都会临场发挥。VideoDirectorGPT 先写场次表和走位图，再开机；失败时可以只改某个框或某个 scene，而不是重写整句 prompt。

当时多数 T2V 模型把一条短 caption 映射为一个短单场景 clip。多场景任务多了三个问题：高层描述没有告诉模型要拆几场；同一个角色跨场景会变脸；自然语言中的“左侧、变小、从右往左”缺乏逐帧空间约束。论文把这三个问题分别交给 scene decomposition、consistency grouping 和 bounding-box trajectory。

timeline title 可控多场景视频的演进 2022 : Latent Diffusion：在压缩 latent 中生成 2023 : GLIGEN：grounding token + gated self-attention 控制图像布局 2023 : ModelScopeT2V：公开 spatio-temporal diffusion backbone 2023 : LLM-grounded diffusion：LLM 生成视觉布局程序 2024 : VideoDirectorGPT：video plan + Layout2Vid + 跨场景共享视觉身份 2024 : VideoStudio / VideoDrafter：继续加强参考图与多场景内容一致性
论文把“长视频”实现为多个短 scene 的组合，关键研究对象是跨 scene 的规划与身份一致性，而非一次生成一个长时域连续镜头。

2. 方法总览

核心一句话：text → editable plan → grounded clips → concatenate。规划器负责决定“拍什么、谁出现、在哪里、哪些出现是同一实体”；生成器负责把这些约束变成每个 scene 的短视频。

flowchart TB P[用户一句 prompt] --> S[GPT-4 第一次调用\nscene descriptions/entities/backgrounds] S --> G[exact-match 一致性分组] S --> L[GPT-4 第二次调用\n8个关键帧边界框] L --> I[线性插值到16帧] G --> E[每个一致性组采样/提供1个 CLIP image embedding] E --> H[grounding tokens] I --> H S --> C[scene text tokens] H --> V[Layout2Vid Guided 2D Attention] C --> V V --> O[逐场景视频拼接]

规划和渲染分开，使人可以在生成前检查 scene 数、对象清单、背景和框轨迹，也可以在生成后定位失败属于 plan 还是 renderer。

3. Video plan：LLM 到底输出什么

符号含义形状/范围

3.1 第一次 LLM 调用：场景与一致性

直觉

先写 call sheet：每场发生什么、有哪些演员和道具、在什么背景。名字完全相同的实体被当成同一角色。

prompt 由任务说明、一个 in-context example 和用户输入组成。GPT‑4 输出四类信息：多场景描述；每场实体清单；每场背景；跨场景一致性分组。论文实际用 exact match 聚合重复名字，例如 {chef:[1,2,3,4], oven:[1]}。这很简单也很脆弱：“chef”“the cook”“he”若未规范化就可能分成三个人。

3.2 第二次 LLM 调用：逐帧布局

直觉

文本说“梨从右推到左”，单张框只告诉模型梨在哪里；一串框才是一条运动轨迹。

GPT‑4 为每个 scene 生成 8 个关键帧框，坐标归一化到 $[0,1]$，格式为 $[x_0,y_0,x_1,y_1]$。in-context 示例以 0.05 为最小步长，相当于 20-bin 量化。生成 16 帧视频时，对相邻关键框做线性插值：

$$l_{i,f}=(1-\lambda)l_{i,k}+\lambda l_{i,k+1},\qquad \lambda=\frac{f-f_k}{f_{k+1}-f_k}$$
是什么
论文明确采用线性插值扩密布局；上式是该操作的标准表达，不是作者编号公式。
逐符号
$l_{i,k}$ 与 $l_{i,k+1}$ 是相邻关键帧框；$f_k$ 与 $f_{k+1}$ 是它们在输出视频中的帧位置；$f$ 是两者之间的目标帧位置；$\lambda$ 表示归一化插值位置。
为什么
LLM 无需输出每一帧的坐标，减少 token 与格式错误；生成器仍获得稠密轨迹。
局限
线性框轨迹不能表达旋转、深度穿越、遮挡关系、关节姿态或物体接触。
一个简化 video plan
{
  "scene_1": {
    "description": "technician approaches the filter cabinet",
    "entities": ["technician", "filter cabinet"],
    "background": "blue utility room",
    "layouts": {"technician": [[.05,.2,.35,.95], ...]}
  },
  "scene_2": {...},
  "consistency": {
    "technician": [1,2,3],
    "filter cabinet": [1,2,3],
    "blue utility room": [1,2,3]
  }
}

字段名为报告重绘示例，表达论文的四类内容；不是仓库可直接消费的官方 JSON schema。

4. Layout2Vid：布局控制、身份共享与训练

Layout2Vid 以 ModelScopeT2V 为 backbone。一个 spatio-temporal block 依次包含 spatial convolution、temporal convolution、spatial attention 和 temporal attention。作者只改造 spatial attention：插入 Guided 2D Attention，保留 scene text 的 cross-attention，并用 layout grounding tokens 经 gated self-attention 调制 visual tokens。

4.1 Grounding token：文字、外观、位置三合一

直觉

“一只白猫”告诉模型类别；参考图告诉它是哪一只白猫；框告诉它这只猫应出现在哪里。缺一项都只能控制部分问题。

$$h_i=\operatorname{MLP}\Big(P_{\mathrm{img}}(f_{\mathrm{img}}(e_i)),\;P_{\mathrm{text}}(f_{\mathrm{text}}(e_i)),\;\operatorname{Fourier}(l_i)\Big)$$
是什么
论文 Eq. (1)，也是 Layout2Vid 最核心的论文独有公式。
逐符号
$e_i$ 是第 $i$ 个实体；$f_{img}$、$f_{text}$ 是 CLIP image/text encoder；$P_{img}$、$P_{text}$ 是可学习线性投影；$l_i=[x_0,y_0,x_1,y_1]$；Fourier 把低维坐标映射为高频位置特征；两层 MLP 融合为 $h_i$。
为什么
文字提供类别语义，图像 embedding 提供实例外观，Fourier box 提供空间位置。可学习投影让不同 CLIP 模态更快对齐到生成器通道。

4.2 训练与推理的视觉 embedding 从哪里来

训练时，$f_{img}(e_i)$ 来自标注框裁出的真实实体图像，因此可以只用 image-level grounding annotation。推理时若用户给参考图，就直接编码；若只有文字，使用 Karlo 的 unCLIP Prior，把 CLIP text embedding 映射到 CLIP image embedding。对 consistency group 中同一实体，只生成/编码一次视觉 embedding 并在所有 scene 复用。这是跨场景“同一个人”的主要身份锚点。

4.3 Guided 2D Attention

直觉

visual tokens 是画布上的像素块，grounding tokens 是贴着名字、照片和坐标的道具卡。gated self-attention 允许画布读取道具卡，同时用门控避免新分支一开始破坏预训练画质。

机制继承 GLIGEN：visual tokens 与 grounding tokens 联合做 self-attention，再把与 grounding 相关的更新通过可学习 gate 加回视觉特征；之后照常用 scene text 做 cross-attention。论文没有给出一个新的、单独编号的 Guided 2D Attention 公式，因此这里不虚构论文公式。可确认的是：默认仅更新 MLP 与 gated self-attention 分支，约占总参数 13%；其余 spatial/temporal backbone 冻结。

4.4 训练目标

论文沿用 ModelScopeT2V latent diffusion 的去噪训练，不提出专有新 loss。其条件化形式可以写成：

$$\mathcal L_{\mathrm{L2V}}=\mathbb E\left[\|\epsilon-\epsilon_\theta(x_t,t,c_{scene},\{h_i\})\|_2^2\right]$$
是什么
对继承的 diffusion objective 的条件化记法，用来说明输入；不是论文编号公式。
逐符号
$x_t$ 是带噪 latent；$c_{scene}$ 是 scene text tokens；$h_i$ 是 Eq. (1) 的实体 token；$\epsilon_\theta$ 是冻结 backbone 加可训练控制分支。
训练什么
默认只训练 grounding MLP 和 gated self-attention；论文消融表明把整个 Guided 2D Attention 都解冻会严重破坏原视频先验。

4.5 布局强度 $\alpha$

生成共 $N$ 个去噪步时，前 $\alpha N$ 步启用 Guided 2D Attention，后 $(1-\alpha)N$ 步关闭布局引导。高 $\alpha$ 更服从框，却可能留下框状伪影或降低自然度；低 $\alpha$ 画面自然，但对象会漂离计划。作者还让 LLM 按 prompt 动态选择 $\alpha$。这不是 loss 权重，而是引导介入多少个去噪步骤。

planner 决定约束，grounding token 编码约束，Guided 2D Attention 执行约束，$\alpha$ 决定执行到多强；四者合起来才是完整系统。

5. 端到端走一遍：机房滤芯检查短片

  1. 输入：“维修技师进入蓝色机房，检查红色报警灯，取出滤芯并复位设备。”
  2. 场景拆分：GPT‑4 生成三场：进入机房；在柜体前检查报警灯；打开柜门取滤芯。每场有 scene description、entities 和 background。
  3. 一致性组：technician:[1,2,3]、filter cabinet:[1,2,3]、blue utility room:[1,2,3]。若 planner 把 “technician” 写成 “repair worker”，exact match 会漏组，生产系统应增加 entity registry。
  4. 布局：scene 2 的 8 个关键帧中，technician 框从 $[.10,.15,.40,.95]$ 移到 $[.42,.16,.72,.95]$；报警灯框固定在 $[.70,.20,.76,.29]$。插值后得到 16 帧轨迹。
  5. 身份 token：用户上传技师制服照时，CLIP image embedding 与 “technician” text embedding、每帧框 Fourier feature 融合；三场复用同一个 image embedding。
  6. 渲染：Layout2Vid 分别生成三段短 clip，前 $\alpha N$ 步强制布局，后续步让画面自然化，再将 clips 拼接。
  7. 商业补层：报警灯颜色、滤芯型号、开门方向和操作顺序必须由视觉检测与 SOP rule engine 验收；二维框不能证明“已断电”或“卡扣已锁紧”。

6. 实验：数据、指标、基线与结果

6.1 设置与指标

  • 单场景布局：VPEval Skill-based prompts，分 Object、Count、Spatial、Scale；ActionBench-Direction 测左/右运动方向。
  • 开放域单场景：MSR‑VTT，随机选 2,990 个测试视频各一条 caption；FID 用 InceptionV3，FVD 用 I3D，CLIPSIM 用 CLIP ViT‑B/16。
  • 多句到多场景：ActivityNet Captions；Coref‑SV 从 Pororo‑SV 构造，专测共指实体一致性。
  • 一句到多场景：HiREST “How to” prompt；planner 自行决定 scene 数。ModelScope baseline 按相同场数追加 “step n/N”。

7. 局限、FAQ 与商业迁移

  • 计划格式脆弱：exact string match 做实体分组；别名、代词、复数和属性变化会漏组。
  • 二维框表达力有限：不能可靠表达遮挡、深度、旋转、骨骼、接触和物理约束。
  • 视觉 embedding 不是完整身份：共享 CLIP embedding 能提升相似感，不能保证脸、服装 logo、产品铭牌逐像素一致。
  • scene 之间是拼接：没有学习转场、镜头语言、音画同步和全局节奏。
  • 基础模型陈旧：256×256、16 帧级别结果与 2026 商业 T2V API 不能直接比较；规划思想仍有价值。
  • 官方限制：项目页明确声明研究用途、不面向商业使用；实际商业化必须重新选择可商用 backbone 与数据许可。
为什么 planner 不能直接写更详细的自然语言？

自然语言很难逐帧约束“在哪里”和“怎么移动”。框把可见几何变成可评估的接口，还允许人拖动编辑。

共享 embedding 就能完全保角色吗？

不能。它提供同一个视觉条件，但扩散采样、姿态、遮挡和 scene text 仍会改变细节。商业系统通常还要参考图 adapter、脸部/产品检测和失败重采样。

70.6% 是否表示 70.6% 视频可交付？

不是。它是 VPEval 四类 layout prompt 的 overall accuracy，主要测对象、数量、相对位置和尺度，不测故事逻辑、动作安全、声音、品牌一致或客户验收。

8. 复现指南与资源核查

不能直接 Quick Start

官方仓库仍只有 README 和展示资源，并明确写 “Code coming soon”。因此不存在可信的官方 clone→install→train/infer 命令；任何声称来自官方 README 的完整命令都将是编造。

8.1 可复现的概念拆解

  1. 用 GPT‑4 或其他 LLM，以 JSON schema 生成 scene descriptions、entities、backgrounds 和 8-keyframe boxes；做 schema validation、坐标裁剪与 entity canonicalization。
  2. 以 ModelScopeT2V 作为论文原 backbone；以 GLIGEN 的 gated self-attention 为 layout 控制来源；CLIP 提供 text/image embeddings；Karlo unCLIP Prior 将文字映射到 image embedding。
  3. 训练数据需有 image caption、实体框和实体 crop。重复同一静态图到视频时间维，只训练 grounding MLP 与 gated self-attention，冻结其余 ModelScopeT2V。
  4. 推理为每个 consistency group 固定随机/参考 image embedding，为每帧更新 Fourier(box)，按 $\alpha$ 切换有/无 layout guidance，最后拼接 scenes。

8.2 复现中最容易错的点

  • 论文项目页说每 scene 生成 8 帧布局再插值到 16 帧；一些二手资料写 9 个关键帧，应以 COLM v2 正文和项目页为准。
  • 不要把 “13% 参数可训练”理解为 LoRA；论文是新增/改造的 Guided 2D Attention 分支。
  • 训练只用图像标注，推理却启用 temporal modules。消融表说明解冻太多 spatial attention 会造成明显错配。
  • Karlo 生成的 image embedding 对同名实体应缓存并复用；若每个 scene 重新采样，就失去一致性设计。
  • 评估 ActivityNet/HiREST 时必须保证 baseline 和本文总 scene 数/总长度一致。

9. 术语表

video plan
scene 文本、实体、背景、逐帧框和一致性分组构成的中间表示。
grounding token
融合实体文本、实体视觉外观和二维位置的控制 token。
consistency grouping
声明不同 scene 中哪些实体/背景应复用同一表示。
Guided 2D Attention
在 spatial attention 中加入布局 grounding 的控制模块。
unCLIP Prior
把 CLIP text embedding 映射到 CLIP image embedding 的先验；本文使用 Karlo。
layout guidance ratio
$\alpha$，去噪前多少比例的步骤启用布局引导。
Coref-SV
基于 Pororo‑SV 构造、测试跨 scene 共指实体一致性的 prompt 集。
