VideoDirectorGPT: Consistent Multi-scene Video Generation via LLM-Guided Planning

Han Lin, Abhay Zala, Jaemin Cho, Mohit Bansal · arXiv 2023 / ICLR 2024 submission
📄 arXiv🌐 Project💻 Code
5 分钟速读
  • 一句话：先让 LLM 把一句提示扩成带场景、实体布局和一致性分组的视频计划，再由 Layout2Vid 生成。
  • 贡献：把“跨场景一致”从自然语言愿望变成显式的数据结构与空间控制。
  • 商业迁移：分支培训、文博叙事和需要固定角色/物件位置的多镜头短片。
  • 局限：它是开放域研究框架，不是可直接交付数分钟商业成片的完整系统。

核心问题

早期 T2V 多生成单一事件，长视频也常把同一动作延长，而不是处理多个场景与事件转折。VideoDirectorGPT 将问题拆成计划和渲染，避免让生成器同时“想故事、记人物、摆位置、画画面”。

flowchart LR A[单句提示] --> B[GPT-4 Video Planner] B --> C[场景描述] B --> D[实体 + 布局] B --> E[背景与一致性分组] C --> F[Layout2Vid] D --> F E --> F F --> G[多场景视频]

方法详解

1. Video plan

计划包含每个场景的文本描述、实体与二维框、背景，以及哪些实体跨场景应被视为同一个对象。LLM 还可以动态调整布局控制强度，处理文本与空间约束冲突。

直觉

剧组不会只拿一句“有人去车站”就开拍；它会先列场次、人物、道具和站位。结构化计划就是生成系统的 call sheet。

2. Layout2Vid

生成器接收场景文本与布局，并用跨场景一致性分组复用实体条件。它主要依赖图像级布局标注训练，却能生成视频，降低视频框标注成本。

3. 一致性不是记忆全部历史

系统显式说明“场景 1 的 woman 与场景 3 的 woman 是同一实体”，只对需要一致的对象绑定条件。这一思路后来在 MovieAgent 与 Soap2Soap 中被扩展为层级计划、资产库与动态视觉记忆。

走一遍例子

  1. 输入：“维修技师进入机房，检查报警灯，取出滤芯并复位设备。”
  2. 计划：四个镜头；技师 ID 和设备 ID 跨镜头复用；每镜头给出人物/设备框。
  3. 渲染：Layout2Vid 按框和文本生成各场景。
  4. 商业补层：真实产品还需 SOP 检查、部件图锚定、动作验证与失败重生成；原论文没有这些安全门。

实验怎么看

论文报告在单场景和多场景设置下，相比当时 T2V 基线具有更好的布局、运动控制和跨场景一致性，并通过用户给定图像、动态控制强度等消融说明各模块作用。指标仍主要衡量视觉与文本/布局匹配，不等于叙事事实或操作流程正确。

商业价值

可复用概念落地方式
结构化 video plan把培训目标、角色、场景和分支变成可审计 JSON
实体一致性分组同一员工、顾客、设备跨镜头绑定品牌资产
显式布局固定危险源、出口、设备与人员相对位置
控制强度在遵守现场几何与视觉自然之间调节

局限与复现

  • 二维布局无法表达遮挡、接触力学和精细手物关系。
  • 跨场景实体分组保持“是谁/是什么”，并不自动保持服装细节、材质和复杂动作。
  • 研究时代的基础生成模型分辨率和时长有限；复现结果与今天的商业 API 不可直接比较。

官方项目和代码提供规划器与 Layout2Vid 资源。复现应按仓库锁定依赖；本调研未运行代码。

术语表

layout
实体在帧中的空间位置，常表示为二维边界框。
consistency grouping
声明不同场景中的实体实例应保持同一身份。
grounded generation
生成结果受可定位实体和空间条件约束。
