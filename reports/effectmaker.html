5 分钟速读

  • 一句话：给它一段参考特效视频和一张新主体图片，生成让新主体呈现相似效果的短片，无需为每个新特效另训一个 LoRA。
  • 痛点：“像样片这样变身”包含形态、附着位置与时间变化，单靠提示词会丢细节，单靠视觉又容易搬错主体。
  • 做法：Qwen 提供理解与适配描述，Wan 同时直接读取参考视频；语义条件用解耦 cross-attention 注入，参考与目标用双流 self-attention 交流。
  • 证据：14 类闭集测试的 VQ、MQ、TA、CAS 均值领先，但部分单类落后。未见效果的证据包含定性案例和类别规模消融，不等于任意特效可稳定迁移。
  • 落地：更适合舞台提案、游戏角色展示、展馆与密室短片等允许挑选修整的素材服务。EffectData 已公开；完整代码与训练权重尚未公开，不能视为即装即用产品。

TL;DR

EffectMaker 将特效定制从“为每个效果训练参数”推进到“使用时直接读取示例”。它没有把视频压缩成文字后就丢弃参考，而是让理解与推理提供语义，让参考 token 提供细节，再通过双流注意力迁移到新主体。EffectData 为这种同效果、跨主体的学习提供大规模合成数据。实验支持双条件与分流投影的有效性，但不证明严格身份保持、可编辑粒子资产或复杂多镜头生产。它为现有调研增加了特效表现层，与叙事编排和几何控制互补。

问题与动机：把“我想要这个效果”变成可迁移的示例

EffectMaker 的标准输入是一段参考特效视频和一张目标主体图片，输出是在新主体上呈现相似特效的视频。任务的难点并非仅仅生成火焰、烟雾或闪光，而是把参考中的变化方式保留下来，同时让变化适应新主体的形状。参考可能是一位人物身边先出现环形光带、再向外扩散；目标可能换成一只宠物。系统需要抽取可迁移的效果，避免把参考人物的长相、服装和背景一并照搬。原文 §3

直觉：顾客给特效师看一段样片，说“我要类似这种出场方式，主角换成我的吉祥物”。只给一句“金色魔法”无法说明光从哪里出现、运动顺序如何、包围主体还是覆盖主体；直接复制样片像素又可能把原人物一起带过来。理想助手先理解“发生了什么”，再观察“具体怎么发生”。

这里存在两种信息损失。第一种是语言压缩损失：把整段参考视频写成提示词，颜色、几何结构、运动节奏会被概括掉。第二种是视觉迁移歧义：仅让生成器读取参考视觉特征，模型可能更容易复现颜色和纹理，却不知道哪部分是特效、哪部分只是参考主体。EffectMaker 的核心设计是让语义理解和视觉示例共同约束生成，并为参考与目标保留不同的表示通道。

因此，下面的脉络不是“更大的视频模型自动解决一切”，而是控制信息逐渐从人工提示、专用参数，转向可以直接阅读的视觉示例。

相关工作与发展脉络

在作者讨论的路线中，MagicVFX 倾向于在指定区域转移参考内容，再通过生成过程细化；这种思路直观，但不同主体和不同构图之间需要处理对应关系。VFXCreator 为不同特效训练 LoRA，把效果沉淀进专用参数；Omni-Effects 用 LoRA-MoE 组织多个效果，缓解独立模型管理问题。它们对应的是“先把效果做成一个可调用的参数模块”。

Video-as-Prompt、VFXMaster 与 EffectMaker 更接近“把参考视频当作临时示范”的路线：生成时读取示例，而不是每新增一种效果就重新制作一套特效参数。EffectMaker 进一步加入 MLLM，对示例与新主体之间的适配关系进行语义分析。应注意这些是任务思路上的关系；Video-as-Prompt 与 VFXMaster 在本文中被称为同期工作，不能画成已经证实的单向继承链。原文 §2

另一个相关脉络是理解与生成的结合。作者选择 MLLM 加扩散生成器的混合结构：理解模型负责抽象、适配和描述，视频 DiT 负责连续视觉细节。这里的“统一”是一个协同框架，并不意味着 Qwen 和 Wan 已合并成同一个 Transformer，也不意味着文字模型直接逐像素生成视频。

方法总览：语义告诉它“做什么”，示例告诉它“怎么动”

理解端采用 Qwen3-VL-8B，接收系统提示、用户指令、参考视频和目标图片。生成端采用 Wan2.2-TI2V-5B。参考内容进入两条路径：语义路径提炼特效的含义和迁移方式；视觉路径保留参考的时空细节。目标图片提供待保留的主体与起始画面。最终生成器在这些条件共同约束下生成目标视频。

语义路径内部还区分两类信号。一类来自 MLLM 最后一层的隐藏状态，概括输入中可感知的多模态信息；另一类来自它自回归生成的分析描述，表达对“效果应该如何作用到新主体”的推断。后者的文字再经 Wan 原有的 T5 文本编码器处理。两类特征通过独立的 cross-attention 分支注入目标视频 token，避免先混成一串后失去各自的表示特点。原文 §3.2–3.3

flowchart TD

 I[目标主体图片] --> M
 U[用户迁移指令] --> M
 M --> H[输入理解隐藏状态]
 M --> P[自回归分析描述]
 H --> C[轻量连接器 / 理解条件]
 P --> T[T5 / 文字条件]

 C --> X[仅作用于目标的解耦 cross-attention]

 X --> D

一句话核心：既不要让文字替代全部参考细节，也不要让视觉示例替代对迁移任务的理解；让两种条件在生成器中各司其职，再通过双流注意力建立联系。

理解这个分工后，公式中的“双流”就容易解释了：它既允许参考与目标交流，也保留了两者不同的身份。

方法详解

1. 理解隐藏状态与生成文字：两个条件到底差在哪里？

“看懂样片”与“解释该怎么改”是两件事。第一种表示可以知道画面里有人、绿色光带和旋转结构；第二种描述才需要回答：目标换成宠物以后，光带应该环绕躯干，而不是机械地贴在参考人物手臂的位置。

作者将一次输入前向计算得到的最后层隐藏状态称为 semantic-understanding features。它们包含输入语义，但这种提取本身没有完成对迁移结果的自回归描述。于是再让 MLLM 生成分析文字，提取 semantic-reasoning features，补充对目标效果的推断。实际注入时，这段推理文字由原有 T5 编码器编码，理解特征则经轻量连接模块适配特征空间。不能把两者都写成“从同一批隐藏状态直接接两根线”，也不能把后一条误称为对视频模型内部思维过程的可验证解释。

解释性记法：两种语义条件

\[C_H=\operatorname{Connector}(H),\qquad C_R=\operatorname{T5}(R)\]

是什么：这不是原文编号公式，而是对 §3.2–3.3 的数据流总结。\(H\) 表示输入理解特征，\(R\) 表示生成的分析文字，\(C_H,C_R\) 是供 DiT 使用的两类条件。

为什么：MLLM 隐状态与 DiT 条件空间不天然一致；轻量连接器承担对接。T5 则沿用基座的视频文字条件入口。连接器具体层宽等细节不能凭“轻量”二字推定。

2. 解耦 cross-attention：同一个问题，分别问两种信息源

目标生成器可以同时问：“这个效果应该表达什么？”和“新主体应该怎样变化？”但若先把两类资料混成同一份表示，难以保留不同来源的特征。解耦分支相当于分开查阅两份资料，再合并答复。

两条 cross-attention 分支共享来自目标视频 token 的 query 表示，却为文字条件和理解条件使用不同的 key/value 投影；最后将两条分支的输出直接相加。这里的“共享 query”与后文参考/目标双流采用不同 Q/K/V 投影，是两个注意力模块里的不同设计，不能互相替代。

解释性记法：解耦分支输出相加

\[Y_t=\operatorname{Attn}(Q_t,K_H,V_H)+\operatorname{Attn}(Q_t,K_R,V_R)\]

逐符号：\(Y_t\) 是语义条件对目标流的更新；\(Q_t\) 来自目标 token；\(K_H,V_H\) 来自理解条件，\(K_R,V_R\) 来自文字条件。这个公式用于教学，论文正文用文字说明该机制，没有给它编号，也未在这里宣称额外可学习权重。

为什么只更新目标：作者明确只在目标 token 与语义条件之间执行 cross-attention，以免参考流受生成目标语义影响。参考应提供可信示范，而不是也被改写成目标主体。

3. 双流 in-context attention：参考与目标能互看，但不共用投影

同一会议中，一人拿着已经拍好的样片，另一人拿着尚未完成的草稿。他们需要互相交流，但不能把样片中的清晰内容和草稿中的噪声当成同一种输入来处理。

参考视频与目标视频先由同一个 VAE 编码器变成潜变量，再 patchify、展平，并沿序列维拼接。不同于全部 token 共用一套 self-attention 投影，作者为参考和目标分别设置 Q/K/V 投影，缓解 clean reference 与 noisy target 的分布差异。两条流随后依然可以对整个拼接序列做双向注意力，输出还会交给后续前馈层处理。原文式 (1)

原文式 (1)：双流注意力

\[\begin{aligned}O_r&=\mathrm{SA}\!\left(Q_r,[K_r;K_t],[V_r;V_t]\right),\\O_t&=\mathrm{SA}\!\left(Q_t,[K_r;K_t],[V_r;V_t]\right).\end{aligned}\]

是什么：第一行更新参考表示，第二行更新目标表示。两行的查询来自不同流，但可读取的 key/value 都来自参考与目标的合集。

逐符号：\(Q_r\) 表示参考 token 正在查询什么，\(K_r,K_t\) 是两条流可匹配的信息索引，\(V_r,V_t\) 是被读取的信息内容。拼接后 key/value 的 token 数为 \(N_r+N_t\)；输出 \(O_r\) 仍有 \(N_r\) 个 token，\(O_t\) 仍有 \(N_t\) 个 token。

为什么：只分开处理不交流，目标无法读取参考的细节；完全共用投影又可能混淆干净示范与带噪目标。这里选择“投影分开、访问共享”，同时获得表示分工与信息交流。

直觉：目标 token 可以从参考中读取光带的局部形状和运动关系，也可以读取其他目标 token 来维持新主体内部一致性。参考 token 在网络内部的特征也会更新；“参考保持无噪声”并不等于“参考隐藏状态从不变化”。

深入：不要把双流误读成一个单向参考检索器

式 (1) 两行都读取 \([K_r;K_t]\)。因此它并未使用一个阻止参考读取目标的单向 mask。它与“只让目标做语义 cross-attention”同时成立：前者是视觉 token 之间的 self-attention，后者是目标 token 对外部语义条件的 cross-attention。论文没有给出完整的标准 attention 展开式；若写 \(\operatorname{softmax}(QK^\top/\sqrt d)V\)，应标为 Transformer 背景，而不是 EffectMaker 新公式。

4. Biased RoPE：既对齐空间，又保留“来自另一个视频”的身份

两段视频的左上角都叫“左上角”，便于空间对应；但它们的第一个时刻不能被当作同一帧。给参考时间轴整体错开，就像把两份同格式文件放在不同编号区间，减少位置身份冲突。

作者使用 biased 3D RoPE：参考与目标的空间位置编码分量对齐，而参考时间位置加入一个常量偏移。可用教学记法 \((\tau,x,y)\mapsto(\tau+\Delta,x,y)\) 理解参考位置的处理，其中 \(\tau\) 是帧的时间坐标，\(x,y\) 是空间坐标，\(\Delta\) 是偏移。这个坐标写法不是原文编号公式；正文只说明常量时间偏移和安全间隔，未报告这里应该取多少。

它并不通过真实时间同步两段视频，也不是对效果播放速度进行显式控制。它解决的是位置表示的区分问题。参考与目标允许不同空间分辨率；因此“空间分量对齐”也不能解读为强制两段视频具有相同像素宽高。

5. 数据与训练：不逐特效微调，不等于训练免费

一个特效师看一次样片就能接新任务，通常是因为过去已经积累了大量经验。EffectMaker 的临时示例能力也建立在训练经验之上：模型先反复学习“同一效果，不同主体”的对应关系，再在使用时读取新示例。

训练阶段从同一特效类别随机抽取参考和目标视频。这个配对方式迫使模型关注跨主体共有的效果，而非只复现某一固定角色。EffectData 的合成流程先组织主体和特效属性，再生成编辑指令、编辑后的终帧以及首尾帧之间的动态过渡；同一效果作用于不同主体的样本组成可采样的配对组。需要区分生成训练数据时的首尾帧模型与用户使用 EffectMaker 时的输入：标准用户不必提供目标终帧。

论文报告约 50k 训练步、32 张 NVIDIA H20，说明这里确实进行了规模化训练。其“无需每种特效再微调”指使用已经训练好的框架时，不必像逐特效 LoRA 那样为每个新例子追加优化，绝不等于整个系统 training-free。原文没有在此提供足够信息让我们断言每个基座模块都全量更新，或者所有基座都冻结。

在加噪时，所有参考 token 和目标首帧 token 保持干净，使用零时间步嵌入；只有目标非首帧 token 加噪并使用相应时间步嵌入。参考因此持续作为视觉条件，首帧持续锚定目标主体。附录的采样时间步采用下式。原文附录 A

原文式 (2)：训练时间步采样

\[t\sim\left\lfloor T\cdot\frac{1}{1+e^{-1.5z}}\right\rfloor,\qquad z\sim\mathcal N(0,1).\]

逐符号：\(z\) 是标准正态样本；将 \(1.5z\) 经过 sigmoid 映射到 0 与 1 之间，再乘总步数 \(T\)，最后向下取整得到 \(t\)。\(\mathcal N(0,1)\) 的两个参数分别是均值和方差。这里 \(t\) 是扩散/流匹配过程的时间步，不是式 (1) 的目标流下标。

为什么：它让训练关注的噪声时间步分布不同于均匀采样。作者用“偏向中间时间步”描述其意图；精确密度还受缩放系数 1.5 和变量变换影响，不能仅凭 sigmoid 变换就断言是以中点为峰值的单峰分布。该式是已有扩散训练策略的采用，并不是论文关于特效迁移的主要新意。

推理时，由目标图片潜变量、待生成部分的高斯噪声潜变量和参考潜变量共同构成输入序列，DiT 在两类语义条件下逐步生成目标。论文配置使用 UniPC 30 步、CFG scale 6、noise schedule shift 16。这些是作者的报告配置，不能据此推出任意分辨率、任意硬件都有同样时延。

走一遍例子：宠物摄影店的“魔法出场”纪念视频

这是教学用假设案例，不是论文已交付的客户项目，也不是对商业收益的实测。假设宠物摄影店已有一段获得授权的样片：一只宠物周围出现蓝色圆环，圆环旋转后散成向上漂浮的粒子。客户提交自己的宠物单主体照片，希望得到相似出场效果。这个案例的收入形式可以是写真套餐附加的视频服务；论文仅提供技术路线，客单价和转化率需要业务试验验证。

  1. 提交输入。系统保存参考视频、目标照片和指令：“保留目标宠物的毛色和姿态，将参考的蓝色圆环与粒子散开效果迁移到它周围。”具体指令为本例编写，并非作者官方提示模板。上传前的单主体检查可减少多宠物关系歧义。
  2. 先做兼容性判断。这里的环绕光效与宠物主体大致兼容；若样片是人物脱去外套后变装，目标却是一块没有衣物结构的石头，就应该让用户改选效果或解释预期，而不是默认“任何效果都能合理套用”。这是产品设计建议，论文没有提供一个自动拦截器。
  3. 理解端分析。可预期的描述内容包括效果的主体外部附着位置、蓝色环形结构、先旋转后碎成粒子的顺序，以及需要保留目标宠物身份。此处列的是人类教学推演，未运行模型，不能当作 Qwen 实际生成的文字。
  4. 建立两种语义条件。理解隐藏状态进入连接器；分析文字由 T5 编码。二者经各自 key/value 分支供目标 token 查询。系统不要求用户自己逐一写出全部光粒运动细节，视觉参考会继续提供这些细节。
  5. 建立视觉示例条件。共享 VAE 编码参考和目标图片，构造参考流与目标流。参考 token 及目标首帧保持干净，目标未来帧从噪声起步；不同 Q/K/V 投影保留流的身份，式 (1) 让目标读取参考。
  6. 生成与验收。经采样得到目标视频后，店员至少检查宠物身份、圆环是否错误穿过身体、先后运动是否正确、粒子出现后是否把宠物也融化。身份失真不能被“特效很华丽”掩盖。高质量通过率、返工次数和每个通过作品的总耗时，才是这个服务的经营指标。

如果这套流程与 SAGE、Soap2Soap 等组成更大的生产链，EffectMaker 更适合作为某个镜头的特效渲染环节：上游决定镜头意图与主体资产，下游负责版本挑选、剪辑和交付。本文没有实证多镜头身份一致性、精确时长控制或对现有目标视频的无损逐帧编辑，因此不宜把它直接包装成长片后期软件的完整替代品。

1. 设置与指标：两套评分，不能混用刻度

闭集测试从 OpenVFX 选取 14 种特效，每类使用 10 张主体图像，按类别汇总视频质量与特效一致性。对手包括逐特效训练 LoRA 的 VFXCreator、使用混合 LoRA 的 Omni-Effects，以及在作者数据上微调 Wan2.2-TI2V-5B 得到的 Wan2.2-FT。论文为了闭集比较，也在相同的 OpenVFX 数据上训练自身方法；但只有 EffectMaker 接收到参考视频，其他方法主要根据特效类别/文本驱动。这个设定能比较“不同完整使用方式的效果”，不能单独证明一个同输入条件下的生成骨干绝对优于其他骨干。

3. 开集证据：未见类别可以迁移，不代表任意特效可复制

观察轴在演示里看哪里与业务验收的区别
效果语义参考是环绕、爆发还是主体变形？生成结果是否发生同一类别的事件？CAS 可辅助判断类别，不保证具体客户设计被完整保留。

目标身份脸、毛色、服装、轮廓在效果最强和高速运动时是否漂移？效果消退后是否仍是同一主体？这是交付核心要求，却没有对应的独立身份保持主指标。

视觉效果“很像”与素材“可以交付”之间，仍有身份、授权、剪辑和格式要求。下面把这些边界与具体商业候选连接起来。

局限与失败：哪些订单应先筛掉？

第一类是快速、大幅运动导致主体保真下降。附录 F 的飞行效果中，主体突然向上起飞时出现身份/外观破坏。参考效果匹配得上，并不意味着人物脸部、肢体和衣物在每帧都能保持。论文把这一问题归因于基础视频模型能力上限；换更大基础模型可能有帮助，但本文没有提供替换后的实验。高速旋转、剧烈翻转等可以作为部署验收时额外设计的压力测试，并非论文已单独量化验证过的类别。

第二类是参考与目标在语义上不兼容。原文举例：参考为“向日葵开花”，目标却是一张狗的图片，生成结果无法忠实表达开花的特效语义。这不是只需提高纹理清晰度的问题，而是“该效果如何作用于这个对象”缺少合理对应。产品应在生成前检查主体类型与特效适配关系，给用户解释或更换模板建议，而不是保证参考视频中的任何动作都能搬到任意商品、人物或动物上。

第三类是合成训练数据覆盖不到真实制作的杂乱条件。主体收集和过滤偏向清楚、居中、单主体的人像与动物；真实素材中的多人互动、遮挡、噪声、不明确的特效边界及多个重叠效果，可能超出该分布。附录的真实电影迁移仍有细节差距。文章没有报告全长影片、连续多镜头统一特效、复杂合成层级或可重建的三维特效场景。

商业上最合适的第一步是建立受控特效模板库：清晰单主体图像、固定长度短片、预先验证的参考效果，生成后人工选片与局部修整。需精确跟踪 Logo/文字、维持产品尺寸、指定每帧运动轨迹、输出透明通道或可编辑粒子层时，应单独验证，论文没有提供这些能力的实验凭证。适用于客户互动活动、角色/宠物纪念短片、游戏社区身份特效等方向的判断属于本调研的产品推断，而不是论文已经证明的商业收入或交付承诺。

商业迁移：把“同一种特效，适配许多主体”卖给谁

以下是基于论文能力的产品推演，不是作者报告的客户案例或已验证收入。EffectMaker 最适合可接受人工挑选与后期修整的短片资产服务：一段已授权参考特效，加一张客户主体图，产出可评审的效果候选。它没有输出粒子系统、透明通道或可编辑 3D 工程的承诺，也不能直接替代游戏引擎特效。

付费方：舞台内容工作室、独立艺人团队		把同一能量爆发 / 冰晶生长参考适配到艺人定妆照，交付每首曲目若干镜头候选及节奏标记；定位为导演与客户的概念评审包。排练前要迅速判断特效气质与角色是否匹配；参考驱动比反复描述“更燃、更空灵”更具体。检查人脸与服装、效果触发点、视觉节奏；同步音乐、超宽屏渲染、无缝循环须由后期完成。原论文不支持实时舞台互动或舞者动作追踪。
独立游戏角色觉醒 / 卡牌稀有度展示短片
付费方：中小游戏美术外包商、卡牌发行团队		保持角色立绘，生成火焰、结晶、数字解体等升级演出候选，交付游戏内播放的成片或宣传之外的角色展示资产。大量角色需共享技能家族风格，同时避免逐角色从头制作；可按角色与效果家族报价。角色辨识度、关键装备、效果类别与重复使用的一致性；需手工剪辑、抠像与适配 UI。输出是视频，不是可实时运行、可交互、带碰撞的引擎 VFX。
密室 / 实景剧本体验中的角色变身片段
付费方：连锁密室运营商、沉浸式戏剧制作方		将授权演员定妆照或原创角色卡适配为“诅咒侵蚀 / 灵魂消散 / 护盾出现”事件片段，嵌入现有触发式播放器。同一剧本在不同门店、演员与节日版本需要换主体，短事件片可复用参考特效。审核演员身份稳定、故事规定的效果顺序和触发前后画面；播放器集成与音效由应用侧实现。当前约分钟级生成，更适合提前制作，不宜承诺游客现场即时产片。

优先试点“舞台概念评审包”或“独立游戏角色展示候选”：交付物允许专业人士筛选，失败成本可控。先对同一参考选取 10 张跨形态主体，记录可用率、修整时间、每条实际 GPU 分钟和最终一次验收比例。客户为节省设计迭代时间付费，而不是为论文的 CAS 分数付费。当前代码与权重未完整公开，适合先做客户需求验证与素材规范设计，不能写成今天即可部署的 EffectMaker SaaS。

与现有维修、手语和社会故事方向的关系较弱：这些场景优先追求动作与语义正确，夸张效果可能干扰目标。与 Soap2Soap、SAGE 的潜在协作则更清晰：它们处理叙事与镜头组织，EffectMaker 负责某个指定镜头的参考特效迁移；这个组合是本报告提出的工程设想，论文没有验证联合流水线。

常见疑问

它是给我上传的完整视频加一层特效吗？

标准任务是“参考视频 + 目标图片 → 新目标视频”，不是“已有目标视频 → 保留原运动并精确合成特效”。它可能重新生成主体运动和画面细节；如客户要求严格保留演员原表演，仍需要另外验证编辑管线或传统合成方法。论文还展示了不输入目标图片的 reference rephrasing 扩展，但这不改变标准任务定义。

既然有推理文字，为什么还要输入参考视频？

推理文字描述大意，参考则保留文字难以完全表达的局部纹理、几何和时间变化。它们解决不同层次的问题。只看文字可能语义正确却不像样片；只看视觉可能颜色很像却未理解复杂形态。论文的双条件消融用于检验这一分工，而不是证明文字思维一定真实可靠。

新效果没训练过，也能复制吗？

参考条件让模型具备向未见效果迁移的可能，论文给了开放类别测试。但“未见”不意味着任何新效果都能成功；复杂快速运动、多个重叠效果、与首帧语义不兼容的效果仍可能失败。商业目录可以先筛选容易稳定迁移的效果，再扩大范围。

可以像后期软件一样锁定某个效果参数和空间位置吗？

本文的主要条件是视觉示例与语义指令，没有给出可保证精确遵循的关键帧曲线、3D 发射器、像素级蒙版和参数化粒子控制体系。若业务必须严格控制安全距离、镜头空间或品牌元素形状，应补充几何控制、合成与人工审核，不能将参考相似度等同于工程精度。

展开 EffectData：怎样制造“同效果、不同主体”的训练对？

作者先整理两类效果：一类是附着于主体或其周围的氛围效果，按元素（如冰、火、光）、表现模式（如粒子、光环）与附着部位组合；另一类是改变服装、身份或物理形态的变换效果。这个分类不是可编辑粒子引擎，而是生成多样化指令的组织方式。

  1. 准备主体。从内部人像与 PPR10K 等来源收集主体图，利用 FLUX 补充男性和动物，过滤文字、多主体与主体过小的图片；以超分辨率和 OCR / FLUX-Kontext 清理等步骤提高输入质量。
  2. 构造静态变化。LLM 根据效果属性写编辑指令，图像编辑模型产生带效果的目标图像。这样先明确“最后希望变成什么样”。
  3. 补上动态过程。MLLM 根据原图与编辑图描述过渡，首尾帧条件的视频模型合成中间运动。数据生产使用终帧，不等于用户推理时需要提供终帧。
  4. 形成配对。同一效果下有不同主体视频，训练时从同一类别抽取参考和目标，让模型学习可迁移的共性。约 13 万 / 3000 类是论文口径，不保证每个类别样本量相等。

数据规模能扩展覆盖，却不能消除合成瑕疵和主体偏差：若制数据模型经常生成同一错误，迁移模型也可能学习它。真实素材中的遮挡、多人和复杂合成层级仍需额外检验。来源：原文 §3.1 与附录 B。

Token此处指压缩视频潜变量按 patch 划分后的一项特征向量，不等于一个文字词语。 T5Wan 原有的文本编码器，将分析描述转换为视频生成器可读取的文字条件。
