5 分钟速读

  • 一句话：把一句创意变成完整短剧，并在写剧本、布置空间、生成镜头和混音之间建立可检查、可局部重做的制作流程。
  • 真正的新意：并非只是让多个 Agent 分工，而是把短剧节奏、共享三维空间和分阶段返工连接起来。剧本不好改剧本；道具位置不对先改提示词；机位变化大则从三维场景重新生成首帧。
  • 核心证据：50 个题材提示的 Short-Drama-Bench 上，叙事连贯性模型评分为 4.62/5，环境布局连续性为 4.05/5；移除三维首帧模块后，后者降到 3.02。
  • 商业意义：适合借鉴为酒店客诉、门店反冲突、保险理赔或博物馆人物故事等多镜头情境内容的生产架构。但这些垂直用途是迁移建议，论文没有验证培训效果或付费转化。
  • 落地门槛：由商业模型 API 和本地三维推理共同组成。作者估计 API 成本约 25–27 美元/成片分钟，公开可运行仓库、素材库与 benchmark 下载尚未核实。

先抓住主线

短剧系统容易把“生成很多五秒视频”误当成“拍出一部剧”。本文把问题拆成三个独立又互相影响的约束：观众为什么继续看、人物和环境为什么没有换位、错误为什么不会一直累积。叙事层使用双检索库和多模型评审；画面层把场景、相机与人物放进共享三维坐标系；制作层把提示词、图像和视频都变成可以返工的对象。结果主要证明这些模块在作者构建的短剧基准上各有作用，而不是证明生成内容已经达到专业商业交付水平。

1. 问题与动机：剧情、场地与返工必须同时成立

像一支没有场记的摄制组

编剧说“服务员把房卡放到桌上”，下一位摄影师只拿到“经理解释房卡问题”，没有人告诉他前一镜头服务员站在哪边、房卡还在不在桌上。他可能拍出漂亮画面，却让房卡突然回到手里、柜台变成走廊。若剧本的证据与反转还依赖这张房卡，视觉错误又会变成叙事错误。本文希望给每一部门共享的剧本状态、空间参照和审核清单。

论文针对的是一句创意输入，而不是已经写好完整剧本、准备好所有人物图像的电影工作流。输入少意味着系统还要替用户解决叙事结构：迅速出现冲突、逐步升级、适时揭示信息，并在场景结尾留下可被画面表现的悬念。单次 LLM 扩写往往会写出概要式故事，缺少能够直接拍摄的行动与道具状态。

第二个缺口是换机位后的连续性。独立生成首帧会改变房间结构；复用上一镜头尾帧虽能保持局部外观，却可能把机位锁住。若尾帧是人脸特写，它根本没有下一镜头需要的柜台、门口与另一人物。仅靠“保持一致”这类文字要求，缺少明确的空间依据。

第三个缺口是生产质量控制。全文中的 reviewer 不只是成片打分器：它在渲染前检查文本能否执行，在图像阶段检查布局和人物，在视频阶段检查物理连续性与进出场。将问题提前到便宜阶段处理，是比无条件多生成几次更有工程意义的设计。

本文研究的是完整制作系统中的可控性；不是提出一个新的基础视频扩散模型。

2. 发展脉络：从组织镜头，到让镜头承担短剧节奏

VideoDirectorGPT 一类工作先把长文本转换成场景与布局，说明语言规划可以成为视频渲染之前的控制层。MovieAgent 等系统进一步拆成编剧、导演和制作任务，但主要解决如何组织长视频。StoryMem 强调跨镜头视觉记忆，可以记住人物外观，却不能自动保证叙事信息分配，也不等价于精确共享三维场地。

本文沿这条“规划 → 分镜 → 渲染”的路线，新增短剧节奏约束和三维空间锚定。它将 MovieAgent、ScriptAgent、StoryMem 以及 Toonflow、小云雀作为比较对象；为不原生接受一句话的基线，作者使用 Claude Opus 4.6 将输入扩展为其所需格式。因此比较是作者整合后的完整流水线比较，不能直接归因于某一个底层视频模型的能力。

flowchart TB A[布局规划：VideoDirectorGPT] --> B[多角色长视频制作：MovieAgent等] B --> C[本文：短剧节奏 + 共享3D + 审核闭环] D[视觉记忆：StoryMem] --> C E[3D重建与人体恢复工具] --> C

与本网站其他论文比较：Soap2Soap 从已有影片获取结构后重拍，本文从一句创意开始创建剧情；SAGE 的切入点是让分镜规则随反馈演化，本文的 reviewer 主要修当前项目；VerseCrafter 与 4Director 侧重几何可控的视频生成后端，本文则在外层生产流程中组合场景重建、人体恢复与图像/视频 API。这里是技术定位对比，不意味着这些系统已经被作者联接或互相引用。

3. 方法总览：先确定故事，再让空间约束跟着镜头走

第一阶段把一句创意扩成可检索的种子故事。系统寻找三类支持：外部事实、因果逻辑、短剧节奏。检索到的素材被压缩成抽象原子，再写成全剧 story core。三位评审独立提出问题，争议交给裁决模型，修改器只替换需要改的场景和依赖字段。

第二阶段把故事变成场景、人物、道具和逐镜头计划，并生成全景与人物多视图。每个镜头有成对提示词：首帧提示描述“拍摄开始时是什么状态”，视频提示描述“接下来发生什么”。第三阶段解决大幅换机位：从共同三维场景中找下一镜头的背景，把当前人物状态注册进去，选出几何可行且符合剧情的机位，再生成新首帧。最后补转场和场景级配乐，统一混音。

核心 idea

让创意可以变化，让已经确定的剧情状态和空间事实尽量不被每次生成重新发明。

flowchart TB A[Story Core：五条跨场景进展线] --> B[场景 / 人物 / 道具资产] B --> C[镜头初始状态 + 结束状态 + 成对提示词] C --> D{尾帧是否足够支持下一镜头} D -->|可直接复用| E[尾帧继续生成] D -->|特写 / 新锚点 / 大幅换位| F[3D世界 + 人物网格 + 候选机位] F --> G[几何过滤 → 语义过滤 → 首帧生成与审核] G --> H[生成视频] E --> H H --> I{视频审核} I -->|失败| C I -->|通过或到重试上限| J[转场与BGM组装]

以下先解释内容状态如何稳定，再解释相机和人物如何落到同一空间，最后说明审核如何决定继续、返工或降级接受。

5. 方法详解

5.1 双原子库：把“好看的套路”与“说得通的因果”分开检索

为什么不能只检索相似故事？

“客人投诉订单取消”可能需要查公司规则，也可能缺少“服务员为什么不能立即退款”的因果依据，还可能开场太平。相似故事只有表面题材一致，未必同时提供这三种支持。本文先诊断缺什么，再走对应检索路线。

约 300 部表现较好的原始短剧被分成两个库。Pattern Bank 有 2,923 个 beat card，记录开场动作、戏剧功能、结尾悬念画面等，提供节奏和包装；Logic Bank 有 6,984 个带重叠的局部文本块，保留人物动机、证据生效条件和后果衔接。前者更抽象，后者保留局部因果上下文。

输入先产生 seed text 和 retrieval plan。fact route 用网页检索满足法律、医学、历史等外部约束；logic route 找局部因果支持；pattern route 按多种 beat 表征的相似度加权排序。随后压缩为 Fact / Logic / Pattern Atoms，再写新故事。论文描述了多视图加权检索，但没有在正文给出可完整复现的权重与统一损失函数，因此这里不补造公式。

重要边界：从已有剧本抽象成原子能降低直接照搬的风险，但不能证明训练、检索和输出已经解决版权授权。医学或法律事实检索也不等于经过领域专家核验。

5.2 Story Core 与辩论式补丁：改错误，保护已成立的剧情

像剧本会里的“修订单”

一个评审想加强反转，另一个担心角色动机崩溃。把两份建议都照单全收可能更乱；整篇重写又可能丢掉原本优秀的悬念。本文让评审必须指出证据、问题对象和修改方向，再裁决争议，最后只替换相关字段。

Story Core 包含全局元数据、逐场景目标与五条跨场景进展线：外部压力、主角响应、解决机制、情绪、知识状态。最后一条特别关键：它记录观众与每个角色此刻知道什么、哪些证据尚未揭露。否则下一场可能提前泄露线索，或让角色凭空知道秘密。

三个独立评审是 GPT-5.4、Claude Sonnet 4.6、Gemini 3.0；针对逻辑、开场、悬念连续、清晰度、反转节奏、结局兑现六项给 0–10 分，并返回 keep strengths、must-fix issues 与可视化执行 gate。确定性聚合合并重复问题，分数差异大、严重性判断冲突或修改方向矛盾时，再由 GPT-5.4 Pro 裁决。修改器输出结构化 patch，局部替换场景计划及其依赖字段。

被删掉但有价值的反转进入 Idea Bank。末轮允许恢复少量创意，条件是不破坏逻辑与可拍性。这是防止“越审越平淡”的设计。它仍是当前项目内的创意记忆，不是像自演化技能库那样证明跨项目持续学习。

深入：镜头级节奏修改为何要分区

场景结构稳定后，首镜头只负责开场吸引力，末镜头只负责明确且可视觉化的悬念，中间镜头承担反转、升级和信息揭露。分别改首、中、末能避免为提升一个分数而重写全部镜头。比如培训片的开场吸引力可以是“风险信号出现”，而不是把冲突夸张成不符合服务规范的桥段。

剧本具备了稳定的知识与道具状态，接下来要把这些状态翻译为可被图像和视频模型分别执行的条件。

5.3 成对提示词与文字审核：静态条件与动态变化分开

“已经拿着”和“伸手拿起”不是同一件事

首帧里房卡已经在客人手中，而视频提示又要求他从柜台拿起同一张房卡，模型会得到矛盾条件。分别写清初始状态与后续动作，才能在昂贵的视频生成前发现问题。

每个 clip script 指定镜头类型、人物、道具、对白/音效、动作、交互、起止状态。Keyframe prompt 管开拍瞬间的构图、人物相对位置、道具和机位；video prompt 管时间展开。Claude Opus 4.6 审核 POSITION、GAZE、ENTRY_EXIT、PROP、CONTINUITY、OVERCROWDING 等问题，输出根因和最小修订建议。道具还单独检查来源、移动、所有权变化及结束状态。

场景资产提供 360° 全景和角色多视图，人物参考来自生成或用户上传的种子肖像。全景负责场地稳定，多视图负责身份、服装和外观稳定；它们约束不同对象，不能彼此替代。

5.4 三维空间锚定之一：先找到一个可靠的首帧坐标

先确定摄影棚，再决定摄影机

一张全景能提供同一房间多个朝向。先从它抽取不同视角，再把人物放进去，至少让各候选画面来自同一个空间，而不是每个镜头都重新造一个房间。

$$B_k=\Pi(P;v_k),\qquad k=1,\ldots,K.$$
是什么
从无人全景 P 按候选视角生成空背景 B。
逐符号
$\Pi$ 是全景到透视投影；$v_k$ 是第 k 个视角；K 是候选数量。随后图像模型结合背景和人物参考生成 $I_k$，VLM 选出 $(B^\star,I^\star)$。
为什么这样设计
不同背景共享全景来源，布局更有共同依据，也方便知道背景相机的已知位姿与内参。
直觉
在同一房间挑机位，而不是根据同一房间描述反复画新房间。

Marble 将无人全景重建为场景世界 $\mathcal W$。但把人物生成到背景里时，图像模型可能顺便改了焦距或视角。系统因此遮掉人物区域，用 VGGT 将生成首帧重新配准到已知背景，并用世界渲染深度与背景估计深度对齐尺度。

为什么还要“登记”生成首帧？

参考照片来自机位 A，不代表修改后的照片仍严格来自 A。只有重新估计偏差，后续相机轨迹和人物位置才有共同起点。

$$T_{I^\star}=T_{B^\star}\Delta T_{I^\star\rightarrow B^\star}.$$
是什么
用已知背景的世界位姿与估计的相对变换，初始化生成首帧的世界位姿。
逐符号
$T_{B^\star}$ 是选中背景相机的已知位姿；$\Delta T_{I^\star\rightarrow B^\star}$ 来自 VGGT 的相对关系；$T_{I^\star}$ 是首帧相机位姿。矩阵组合顺序沿用论文定义，不能脱离坐标约定任意颠倒。
为什么这样设计
它修正人物插入造成的小幅视角漂移，背景区域继续优化旋转、平移和焦距。
直觉
先把“生成画面从哪里拍的”放回摄影棚地图。

5.5 三维空间锚定之二：把视频尾帧的人物交给下一机位

相机和演员要在同一张地图上

视频模型可能让人物走动、摄影机推进。只知道第一帧机位不够，还必须恢复尾帧的机位和人物位置，否则新镜头会把演员送回开场位置。

$$T_t=T_{I^\star}\Delta T_t.$$
是什么
将视频中的局部相机轨迹锚定到场景世界。
逐符号
CUT3R 对采样帧恢复局部轨迹、深度与内参；$\Delta T_t$ 是第 t 帧相对首帧并完成尺度校准的位姿；$T_t$ 是对应世界位姿。
为什么这样设计
不同 clip 的相对恢复各有自己的坐标系，只有接到共同首帧世界位姿，才可以比较跨镜头人物站位。
直觉
把各段视频自己的“小地图”接到同一张“大地图”。

系统在局部时间窗口以背景颜色、边缘、深度一致性细化尾帧位姿。SAM 3D Body 恢复尾帧的人体网格和关键点，SAM3 给出人物 mask；将网格配准后，相机、人物、场景共享坐标。下一机位在人物附近球壳上改变方位角、半径和高度采样。

两级筛选：几何过滤拒绝离表面太近、脸被严重遮挡、有效背景太少的机位；VLM 语义过滤检查剧情要求的场景锚点是否可见，例如“门口出现经理”要求门口在镜头中。保留 top-8 视角，分别渲染背景和人体网格；网格约束姿态、轮廓和视角，多视图人物参考维持身份服装，上一尾帧维持局部状态。最终图像模型生成新首帧。

深入：多人镜头不是把所有人物都从尾帧硬抠出来

如果另一人物在尾帧不可见，系统向前搜索最近的可见帧，用该视频前缀的 CUT3R 轨迹找对应机位，再恢复此人的网格。沿相机到人物的射线前后移动网格，以轮廓与 SAM3 mask 匹配并保持关键点对齐，减少深度歧义。之后以多人中心采样相机，要求所有必需人物可见且大小合理。这里依赖几何估计质量；没有证明所有遮挡或快速交互都能正确恢复。

几何给出可行约束，并不保证生成模型完全服从，所以首帧和动态视频仍要单独审核。

5.6 分层审核：不是每个低分都整段重拍

不能靠平均分掩盖一项致命缺陷

画质满分但主角缺失，不能因为总分高就通过。审核规则因此既有均值，也有不能被其他优点抵消的硬门槛。

$$\mathrm{accept}_{\mathrm{image}}=\mathbf1[\min_j q_j\ge3],\qquad \mathrm{rank}=\sum_{j=1}^{6}q_j.$$
是什么
本报告对附录 J.2 规则的整理，非论文新增训练公式：首帧六项均过门槛才进入总分排序。
逐符号
$q_j$ 是时间连续、布局、背景、人物场景交互、人物完整和颜色连续六项之一，每项 0–5；$\mathbf1$ 是条件指示函数。
为什么这样设计
任何一项低于 3 就拒绝；接受集合中选 0–30 总分最高者，避免一项严重失真被其他项抵消。
直觉
先保证没有明显短板，再选整体最好。
视频还要检查演员有没有按剧本进出场

人物突然冒出来和人物外观不够像，是两种不同错误。本文的 presence gate 检查出现、离开及在画面中的状态顺序，不是身份相似度指标。

$$\mathrm{accept}_{\mathrm{video}}=\mathbf1[(p+c+r)/3\ge5\;\land\;h=10].$$
是什么
本报告将附录 J.3 的视频通过条件写成公式。
逐符号
$p,c,r$ 分别是物理完整、时间连续、反应合理，均为 0–10；$h$ 是人物出现状态一致性，只取 0 或 10。
为什么这样设计
普通视觉项的平均分至少 5，同时人物进出场必须完全通过。失败时回写提示词或重新生成视频。
直觉
画面及格还不够，演员必须按照这段故事该有的状态出现。

图像/视频审核使用 Qwen3.5-397B-A17B。文本、首帧与视频失败项最多修订或重新生成三次；仍失败时保留 reviewer 分数最高的候选。所以“输出成片”并不表示全部硬约束最终通过。对实际交付应保留未通过状态，而不能只给用户一个看似成功的文件。

5.7 后期：让场景关系和情绪可被听懂

时空连续用直接切换；同地跨时用时间过渡及文字；换地点用建立镜头；局部移动有叙事意义时使用走廊等动作桥接。配乐库共 8,122 首，描述统计有 8 大类、40 子类，实际匹配还使用 16 个功能桶，这两种分类不应混写为同一层级。

LLM 从场景与情绪选择主/备用桶，GPT-Audio 依据情绪、叙事、节奏、转场契合度给候选片段打 0–10 分并选最高者。混音按对白密度降低底音量、根据 LUFS 差校准响度，再用保留语音的动态压缩在对白时压低音乐。它关注的是一个场景跨镜头的音乐连贯，不是给每个镜头随机配一首音乐。

6. 走一遍例子：酒店订单取消的培训小剧场

以下是依据论文机制构造的教学推演，未运行系统，不是论文样例或实测结果。目的在于展示模块交接，而非预测生成质量。

  1. 输入：“客人深夜抵店发现订单被取消，前台在不激化冲突的情况下查明原因并提供处理选项。”额外业务资料是酒店自己的订单流程与补偿权限；这属于商业迁移时新增的事实约束。
  2. 检索计划：Fact Atoms：取消原因须以订单记录确认、不能先承诺超权限补偿；Logic Atom：前台先确认姓名与订单号，经理之后才获得处理所需信息；Pattern Atom：用“客人出示确认邮件，但屏幕显示取消”作为可视化冲突。不能把网上相似纠纷当成本酒店制度。
  3. Story Core：场景 1 发现冲突，场景 2 核验记录，场景 3 提出选择。知识状态明确：客人起初只知道收到确认邮件，前台核验后才知道支付渠道状态。评审发现“经理第一镜头就说出原因”泄露了尚未获取的信息，patch 只改这一对白及对应知识字段。
  4. 镜头状态：clip A 开始时客人持手机、前台空手；结束时手机仍归客人、订单号已输入。clip B 是柜台反打，经理从侧门进入。Keyframe prompt 不预先让经理站在柜台前，video prompt 再描述进入动作。
  5. 共享空间：示例采用米制自定义坐标：柜台沿 x 轴，客人中心 (0, −1, 0)，前台 (0, 1, 0)，经理由 (2, 1, 0) 进入；这些数值用于解释，不是论文参数。全景世界提供柜台与门口位置，恢复人物后相机绕多人中心采样。
  6. 换机位：上一尾帧为客人手机特写，缺少门口信息，因此不能直接当下一首帧。几何过滤拒绝柜台内穿模机位，VLM 拒绝看不到侧门的机位；剩余视角生成“柜台+经理入口”的首帧。
  7. 审核与返工：假设一个首帧六项分数为 (4,4,2,4,4,4)，虽然总分 22/30，背景项低于 3，仍应拒绝。另一个生成视频的 p,c,r 为 (7,6,5)，均值 6，但经理未按顺序进入、h=0，同样拒绝。这些评分只用于演示门槛。
  8. 组装与交付：不跨时空的对话直接切换；解释方案时降低音乐，并输出带业务审核记录的版本。还应追加服务专家确认“话术正确、动作符合流程、未承诺错误权益”，这一步超出原论文。
论文可借鉴的是“状态 → 空间 → 审核”的生产逻辑；培训合格还需要业务规则与学习效果评估。

10. 局限：工程复杂性与评估偏差仍然存在

  • 作者承认的成本与交互问题：多级审核和 3D 建世界增加成本；目前人工交互较有限，未来希望把边缘样本交给用户选择，减少无谓重试。
  • 空间约束不是精确仿真：由生成全景重建的世界、估计相机轨迹与恢复人体都有误差。它们提供相对稳定的空间依据，不证明毫米级位置、真实碰撞或可靠工具操作。
  • 审核有截止条件：最多三次重试之后会保留最好候选，可能仍不合格。自动评审分数不等同于消除错误，采样帧审核还可能漏掉帧间短暂异常。
  • 公平性与归因：完整系统组合不同商业 API 与本地模块，基线又要做输入适配。结果能支撑整体流程有效，不能把全部提升归因于多 Agent、3D 或某个模型的单项优越。
  • 基准规模与泛化：50 个题材由作者设计，包含常见爽剧结构，不能直接外推到低戏剧性的流程演示、专业手部操作、无障碍手语或精密设备维修。
  • 资源与资产：正文说明补充材料含代码，但可公开运行资源未核实；300 剧本与 8,122 音轨的完整来源、使用许可与分发权限仍需逐项确认。royalty-free 不等于无需满足任何授权条件。

11. 常见疑问

这篇比 MovieAgent 更适合加入商业场景调研，原因是什么？

它把一句话创意、质量审核、跨镜头空间和后期做成完整闭环，还给出短剧专属消融、运行时间和成本估计，因此更方便分析生产流程与单位成本。但可复现性并不更强：公开仓库还没有核实，许多环节依赖商业 API。

它已经实现“一个提示词自动拍出合格的商业短剧”了吗？

实验展示的是作者框架产出与 benchmark 评分，不包含商业客户验收、付费意愿、完播率或重复修改后的成本验证。重试上限之后仍会输出最好候选，自动完成与商业合格必须区分。

为什么不把上一尾帧一直传下去？

局部延续时有用，但人脸特写不包含房间布局；大幅换机位还要求看到旧画面之外的区域。系统检查是否缺少新的场景信息，必要时走三维首帧路径，而非一律尾帧接龙。

与 VerseCrafter / 4Director 的几何控制可以直接拼起来吗？

概念上可把后者当更可控的视频生成后端，但本文首帧/人物网格/相机接口并不自动等于它们要求的动态几何条件。需适配坐标、时间、深度尺度、人物表示和视频长度，并重新实验；目前没有联合效果证据。

这篇有必须复现的训练公式吗？

核心是系统编排和几何注册，没有新的基础视频模型训练目标。真正应复现的是检索语料、提示与状态 schema、相机/人物锚定、审核门槛和重试策略。给它附上通用扩散损失反而会误导贡献定位。

  3. 获得自有或授权剧本和音乐后建立双库。若使用不同于原文的 300 剧本、2,923 beat、6,984 chunk 或 BGM 库，应标注为重新实现，不能宣称严格原样复现。
  4. 确认各 API 模型的可用性、版本、图像/视频尺寸、音频接口与素材许可。论文未给出所有端点和完整版本锁定，随意替换可能改变实验结论。
  5. 单独验证一个场景中的全景重建、首帧配准、CUT3R 轨迹尺度和人物网格注册，再接跨镜头。先看相机与人体是否共坐标，不要只用生成图像“看起来像”作为几何验收。
  6. 按原文首帧六项门槛、视频 presence gate、最多三次重试和 top-8 相机设置保留详细日志。统计重试次数、未通过率、耗时和真实账单，才能检验成本估计。
  7. 复现表 1–2 时固定相同 50 提示，保留基线输入扩展，并将内部生成审核与外部最终打分分开。报告随机种子或 API 重复采样、方差与评审差异；若无法获得原版模型或库，明确结论仅适用于替代配置。

12.3 硬件、时间和费用

论文附录 G 报告本地模块可在单张 NVIDIA RTX A6000 48GB 上运行，主要显存压力来自 CUT3R；VGGT、SAM 3D Body、SAM3 和渲染也在本地。作者称可改 CPU，但明显更慢，没有提供可核实的最低 CPU 内存与速度承诺。外部生成仍靠 API，48GB 卡不是“整套模型离线运行”的要求。

按附录 H，完整约十分钟短剧的编剧/改写约 10–15 分钟，图像资产并行生成约 2–4 分钟，建每个世界约 2–4 分钟，视频生成接近一小时，总计约 74–90 分钟。这些是作者测试时的近似墙钟时间，受排队、重试和场景数影响，不是 SLA。基线硬件也不完全一致，StoryMem 用 H200，因此不要据运行时间直接推导同硬件算法加速倍数。

12.4 最容易踩的坑

  • 全景重建尺度、VGGT 深度尺度与 CUT3R 相对轨迹没有对齐，会得到视觉上合理却位置漂移的结果。
  • 把图像生成器输出当成原背景相机，不重新注册，首帧小误差会传播到后续镜头。
  • 用只见主角的尾帧恢复所有人物，可能把遮挡角色摆错；应检索此前最近可见帧。
  • 把人物进出场审核误作身份一致性审核，或把模型评分误作人工打分，都会高估系统可靠性。
  • 忽略重试、图像修复、世界构建与专业审片，只计算视频秒价，单位成片成本会被低估。

13. 术语表

Logline
一句话的故事设想，通常表达角色、处境和核心冲突。
Beat / Pattern Atom
承担某种戏剧功能的节拍，以及抽象后的可复用节奏模式。
Logic Atom
支持角色动机、证据生效与后果衔接的局部因果信息。
Story Core / Story Bible
统领角色、场景及跨场景状态的结构化故事规划。
Patch-based Revision
局部替换指定字段及依赖内容，保留未受影响部分的修改方式。
3D Grounding
将画面、相机与人物位置关联到同一三维参考空间。
Registration / Scale Ambiguity
配准是对齐不同估计的坐标；尺度歧义是单目恢复通常不能独立确定绝对尺寸。
Blocking
人物在场景中的站位、移动及相互关系。
Reviewer / External Judge
前者在生成时触发修订，后者在最终评估时衡量方法结果。
LUFS / Ducking
感知响度单位；在对白出现时降低配乐音量以保证清晰度。
